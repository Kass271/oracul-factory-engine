# Oracul factory speed-up plan

Status: **WAITING — implement only when the user says "implement all"** (2026-10-04, updated with A11 + Playwright-config
migration). Nothing implemented yet. Independent of
`plans/2026-10-04-red-gate-and-stack-fix.md` (the correctness plan); see "Overlap" at the end.

## Goal
A simple-feature slice took ~3 h. Target: ~1 h, without weakening any gate.

**Principle: related tests while developing, the whole suite once when the slice works.**
- Development loop (tester self-check, red gate, builder loops, per-round verify and E2E): only the tests related to the
  slice — its `@trace`-tagged tests, the tests listed under "Changes earlier behaviour", the test files changed in the
  working tree, and the tests that failed in the previous run.
- Slice gate (before review and close): **full verify** (all unit + integration tests, coverage ratchet, all checks) and
  the **full E2E suite**, both green on the final code. DONE is impossible without them. Step 5 keeps its full run.

## Evidence (measured 2026-10-04, app `oracul-engine`, phase-02)
- Workflow runs: red 28m36s (4 agents, 442k tok) · red retry **41m12s (2 agents, 61k tok)** · green 22m27s (30 agents, 865k tok).
- The 41-minute retry: one tester, 31 tool calls, 38k tokens — almost all of it waiting on full suites. It made a small
  correct fix, then chased **flaky older ITs** (`InsufficientEvidenceIT`, `EventNormalizationIT`: "core size of K(2,3)
  expected 2 but was 0", a different one each run) that red-check blamed on the new tests: ~8 full backend runs.
- One full backend run is close to 10 minutes (the tester fell back to `sleep 500` / `pgrep gradlew` polling because
  red-check no longer fits the 10-minute foreground limit).
- Unit tests from cache are cheap (verify: backend 1 s cached, frontend 8 s / 473 tests).
- E2E: ~105 Playwright tests; an earlier full run took 9.5 min; one shared failure (`chatgpt-status`) failed 12 tests.
- Docker: no `.dockerignore` in the template (context = whole app incl. node_modules, build output, .git, sent twice);
  backend image downloads Gradle + all dependencies on every build; copying `backend/` includes tests, so any test
  change forces a full rebuild.
- An agent in the app session, refused by `stack.mjs e2e --scratch` (the app's `e2e/playwright.config.ts` predates
  `E2E_REPORT_DIR`/`E2E_OUTPUT_DIR` support), improvised: it ran Playwright directly "with list output and a separate
  results folder". That bypasses the stack lock and can overwrite QA screenshots (`evidence()` writes to
  `docs/…/05_release/qa/screenshots` unless redirected) and, if the CLI reporter doesn't replace the config's, the
  official `results.json`.

| # | Cause | Fix (work package) |
|---|---|---|
| C1 | Flaky older tests + gates that blame the slice for any older failure → random WRONG-REASON / RED, investigation loops | A3 + B1 (FLAKY classification via one retry) |
| C2 | Every check runs the full ~10-min backend suite (self-check, red gate, builder loops, every round's verify) | A2, A4, A5 (related tests while developing) |
| C3 | Tester self-check has no limit ("until RED") | A2 (max 3 runs, stop on causes it can't fix) |
| C4 | Full E2E + Docker rebuild in every round | A6, A9, B1 |
| C5 | Both builders run in every round, even for one-layer failures; ~10–12 Haiku runner calls per round | A7 |
| C6 | 12 identical E2E failures look like 12 problems | A8 |
| C7 | Step 5 reruns a full E2E that already passed on the same code | A10 |
| C8 | No timings anywhere — causes are estimated, not measured | A1 |
| C9 | Old app Playwright config has no separate report dirs → scratch/focus runs refused → agents run Playwright directly, unlocked, risking official evidence | A6 fallback, A11, B2 |

## Design rules (so the work can land while a slice is paused)
1. No new subSteps, no renamed or removed state fields, no doc-format changes (red-evidence, specs, plan unchanged;
   only additive). A slice paused mid-stage resumes with "continue" under the new engine.
2. Never weaken a check (AGENTS.md rule 1): every scoped run is a development aid; the slice gate stays full.
3. Every change to a check, hook, state command or bin script has a red and a green case in `self-test/run.mjs`.
4. Node built-ins only in engine scripts. Workflow scripts: `export const meta` first, no `Date.now()`/`Math.random()`/`new Date()`.
5. Part A = engine only (takes effect on "continue"). Part B = app files; applied only between slices (subStep `none`).

## Decisions (defaults used unless overridden in the run prompt)

| # | Decision | Default |
|---|---|---|
| D8 | Do flaky tests ever block? | **Never block.** Recorded in `state/apps/<app>/flaky.json`, shown by `status` and in the final report under Problems; a test flaky in ≥2 slices is marked "persistent" |
| D9 | Red gate (orchestrator's red-check) scope | **Related tests** (`--scope slice`). Older-test breakage then surfaces in the slice gate's full verify and goes to the tester through triage |
| D10 | Review in parallel with E2E (S4 from the analysis) | **Deferred** — the guard is subStep-based; running the reviewer during subStep `e2e` would leave it unguarded. Needs its own design |

## Part A — engine only

### A1: timings (measure)
- `state.mjs set subStep` appends `{at, app, slice, round, from, to}` to `state/apps/<app>/timings.jsonl` (append-only;
  a logging error never fails the command; `state.json` format unchanged).
- verify, red-check and stack print `took <n>s` per layer / phase.
- verify and red-check print the 10 slowest test classes (JUnit XML `time`) and the number of Spring contexts started
  (count of "Started … in … seconds" in the XML system-out).
- `status` skill: time per subStep for the current and last slice.
- Self-test: a transition is logged (green); malformed lines are skipped by the summary (green); a read-only state dir
  doesn't fail `set subStep` (green); slowest-classes table from a fixture XML (green); missing XML → no table, no error (green).

### A2: related-tests red-check, capped tester self-check (C2, C3; D9)
- `red-check --scope slice`: backend `./gradlew test --tests <class> …` for the slice's tagged test classes + changed
  backend test files; frontend: the runner's file filter for tagged + changed spec files. If the frontend runner has no
  file filter, the frontend part runs in full and says so.
- Verdict rules unchanged for the tests that ran (NOT-RED, compile, test-bug signatures, superseded-not-updated,
  ranges). "Older test fails" can't happen in a scoped run; it moves to the slice gate.
- `red-evidence.md` records `Scope: slice` (additive line; missing = full, so old files still pass).
- `--scope full` stays available (and is what Step 5 / regression uses).
- Tester (`agents/tester.md`, `testing-rules`, workflow prompt): self-check with `--scope slice`, **at most 3 runs**;
  stop at once and report when the remaining failure is outside its control — `Task :compileJava FAILED` (production
  compile), a FLAKY older test (A3), a startup failure caused by production code. Never poll with `sleep`; scoped runs
  fit the foreground limit.
- Orchestrator (`skills/factory/SKILL.md` Step 4.2): `red-check --slice <s> --scope slice`.
- Self-test: scope builds the right `--tests` list from the fixture (green); a changed untagged test file is included
  (green); an unrelated older test is not (green); `Scope: slice` written (green); old evidence without the line passes
  check-artifacts (green); slice not in plan → error (red).

### A3: FLAKY classification (C1; engine part; D8)
- `junitFailures` groups testcases by class + name. A test with a failed attempt **and** a passed attempt (what the
  Gradle test-retry plugin writes, B1) is FLAKY. Without the plugin there are no repeats → today's behaviour exactly.
- red-check: older untouched test FLAKY → warning line + `flaky.json`, not WRONG-REASON. Slice-tagged or changed test
  FLAKY → **WRONG-REASON "flaky new test"** (new tests must be deterministic). Fails on every attempt → today's rules.
- verify: Gradle exits 0 when the retry passes (`failOnPassedAfterRetry=false`); verify prints `FLAKY: <test>` lines and
  updates `flaky.json` (first seen, last seen, slices). A test in ≥2 slices is "persistent".
- Final report and `status`: flaky tests under Problems.
- Self-test: older fail+pass → FLAKY, verdict RED (green); slice fail+pass → WRONG-REASON (red); older fail+fail →
  today's message (red); verify writes flaky.json and marks persistent after 2 slices (green); XML without repeats →
  unchanged result (green).

### A4: builders loop on related tests (C2)
- `agents/backend-builder.md`, `frontend-builder.md`, workflow prompts: loop on the slice's tests
  (`./gradlew test --tests …` for the classes in red-evidence.md + tests in the fix list; frontend file filter), then
  **one** full run of their layer before finishing.
- Integrity self-test (frontmatter) still passes.

### A5: per-round verify on related tests, full verify as the slice gate (C2)
- `verify --scope slice`: related tests only (same selection as A2 plus the previous run's failures), then the checks
  that don't need full reports (contract, artifacts, review, traceability of the slice's FRs). Coverage ratchet is
  skipped and says so. `lastVerify` records `scope: "slice"` (additive field) and `--reuse-if-fresh` never reuses a
  scoped run.
- Workflow green loop: fix rounds use `verify --scope slice`; when it is green → full `verify` (the slice gate). Full
  RED → triage → next round (scoped on the new failures). Close keeps `verify --reuse-if-fresh`, which only accepts a
  full GREEN run.
- Self-test: scoped verify never satisfies `--reuse-if-fresh` (red); full GREEN does (green); scoped run skips coverage
  with a message (green); selection includes the previous failures (green).

### A6: related E2E per round, full E2E as the slice gate (C4)
- `bin/e2e-focus.mjs --slice <s> [--failed-from <results.json>]` prints the E2E files: the slice's `@trace` E2E specs,
  the e2e files under "Changes earlier behaviour", and the previous run's failures.
- `stack.mjs e2e --detach --focus <files>`: same lock, separate report/output dirs (like scratch, checked by
  `scratchEnvProblems`), never writes official reports, traces or QA screenshots.
- Workflow: round 1 runs the **full** suite (it is needed anyway). Later rounds: focus run first; when it is green → full
  official run. DONE requires a full official green run whose inputs (image hash A9 + `e2e/tests` hash) match the final
  code; the close step checks this.
- **Fallback for apps without scratch support** (`scratchSupported(config)` false — e.g. this app before B2): every
  round runs the **full official** E2E instead of a focus run. Slower, but correct; never an improvised direct run.
- Self-test: focus list from fixture (green); focus env pointing at official dirs → refused (red); dry-run plan of a
  focus run (green); close with a stale full-run hash → refused (red); matching hash → passes (green); config without
  scratch support → the workflow's plan is a full official run, not a focus run (green) and never a direct Playwright
  call (red).

### A7: route work to the failing layer, fewer runner calls (C5)
- Triage schema adds `layers` per code item (`backend` / `frontend`; unknown → both). Review findings route by file
  path. Round 1 always starts both builders.
- Fold `round +1` and `set subStep` into the next gate command; notes join the following state change. Every gate keeps
  its own `ORACUL_EXIT` sentinel.
- Workflow integrity self-test; smoke covers a one-layer fix round.

### A8: group identical E2E failures (C6)
- `failureBlock` groups failures whose first error lines are identical: `✘ 12 tests: Locator chatgpt-status expected
  "ChatGPT connected"` + their titles; budget unchanged.
- Self-test: 12 identical + 1 different → 2 groups (green); budget respected (green); single failure → as today (green).

### A9: skip the Docker rebuild when images are current (C4; engine part)
- `stack.mjs up`: hash of the **whole build context minus an explicit exclude list** (tests, `*.spec.ts`, docs,
  node_modules, build output, reports, `.git`). Unknown files are included, so a missed input means a rebuild, never a
  stale image. Same hash + healthy containers → `up -d` without `--build`. Stored in `state/apps/<app>/stack-hash.json`.
- Self-test (dry-run): same inputs → no `--build` (green); `src/main` change → `--build` (red case for a skip);
  spec-only change → no rebuild (green); unknown new file → rebuild (green).

### A10: Step 5 reuses a matching full E2E run (C7)
- `finish-and-run.js`: if the last official full E2E run is green and its hash (A6) matches the current code → print the
  reuse line and skip; otherwise run.
- Self-test: matching → reuse (green); changed → run (red case for reuse).

### A11: E2E only through stack.mjs — no improvised runs (C9)
- **Guard** (`hooks/guard-edits.mjs` `stackViolation`): while an app is active, block running Playwright directly in
  **every** subStep (not only red/green/test-fix/review). Recognise every form: `npx|pnpx|bunx playwright test`,
  `yarn|pnpm [exec] playwright test`, `npm exec|x playwright`, `./node_modules/.bin/playwright test`, `node …/playwright/cli.js test`,
  `node …/@playwright/test/cli.js test`, and `npm run|test` inside or with `--prefix` `e2e`. Mutating `docker compose`
  / `docker` container commands are blocked in every subStep too. Allowed as today: `stack.mjs` (its own subStep
  rules), `stack.mjs status`, read-only `docker compose ps|logs`, unit tests. Playwright started *by* stack.mjs is a
  child process, not a tool call, so the official path is unaffected.
- **stack.mjs refusal messages name the fix:** scratch/focus without config support → "e2e/playwright.config.ts lacks
  E2E_REPORT_DIR/E2E_OUTPUT_DIR support — migration pending (migrate.mjs --speed at the next slice boundary). Do not run
  Playwright yourself; the workflow's official E2E step covers this round." Exit 1.
- **One rule, everywhere it matters** (`testing-rules`, `agents/tester.md`, builder agents, `skills/factory/SKILL.md`,
  `skills/run`): if `stack.mjs` refuses, report the reason and stop; never run Playwright or docker compose yourself.
- Self-test: one red case per Playwright form above in subSteps `none`, `test-fix` and `green`; `stack.mjs e2e` in
  subStep `e2e` allowed (green); `stack.mjs e2e --scratch --grep x` in test-fix allowed (green); `docker compose logs`
  allowed (green); `docker compose up` in subStep `none` blocked (red); refusal message contains the migration hint (green).

## Part B — app files (between slices only)

### B1: templates for new apps
- Backend: Gradle `org.gradle.test-retry` plugin, `retry { maxRetries = 1; failOnPassedAfterRetry = false }`
  (backend only; the frontend suite is fast and not flaky).
- `templates/app/dockerignore` → `.dockerignore` (scaffold writes it, like `gitignore`): node_modules, build output,
  reports, test results, `.git`, docs, `e2e/`.
- Backend Dockerfile: copy wrapper + build files first, dependencies with `RUN --mount=type=cache,target=/root/.gradle`,
  then `src/main` only, `bootJar` with the same cache mount. `env-check`: BuildKit available.
- Smoke proof: a test that fails once then passes → FLAKY and verify GREEN; second `stack.mjs up` with only a test
  change → no rebuild; image rebuild after a `src/main` change uses the Gradle cache.

### B2: migrate the existing app
- `bin/migrate.mjs --speed` (shared with the correctness plan's WP-M), idempotent, run from the app session at subStep
  `none`: adds `.dockerignore` if missing; patches the Dockerfile and the test block only if they match the known old
  template text — otherwise refuses and prints the manual change. Then `verify` GREEN, then commit.
- **Also patches `e2e/playwright.config.ts`** to read `E2E_REPORT_DIR` and `E2E_OUTPUT_DIR` (as the current template
  does), only if it matches the known old template text; otherwise refuses and prints the change. After it, scratch
  runs and A6 focus runs work for this app; before it, A6 uses its full-run fallback.
- **Automatic at slice boundaries:** `skills/factory/SKILL.md` Step 4.1 (before `next-slice`) runs
  `migrate.mjs --speed --check`; exit 10 = migration pending → `migrate.mjs --speed`, `verify` (must be GREEN),
  `commit.mjs --message "<phase> migrate: speed"`, then continue. Only at subStep `none`; never mid-slice. A refused
  file is reported to the user once and the build continues without that part. No manual step for the user.
- Self-test: first run applies, second changes nothing (green); customised Dockerfile → refused, not overwritten (red);
  `--check` → 10 when pending (green), 0 when done (green); `--check`/apply at subStep ≠ `none` → refused (red);
  old Playwright config → patched and `scratchSupported` true afterwards (green); customised config → refused (red).

### B3: faster suites (guidance)
- `testing-rules`: one shared IT base class / one Spring context (no per-class `@MockitoBean` variations), singleton
  Testcontainers; async assertions wait on a condition, never a fixed sleep. Reviewer checks it under "tests".
- No runtime change; the app's slow and flaky tests are improved in later slices (A1 shows which ones).

## Pause, run and automerge
- Implement in a git worktree on branch `speed-up`; main (which the app session loads as the plugin) stays unchanged
  until the merge, so app development can continue while the work is built.
- Automerge only when: every work package's self-test is N/N; `node self-test/smoke.mjs` is green (needs the environment
  from `bin/env-check.mjs`); main hasn't moved or the branch was rebased and re-tested; the prompt says `App paused: yes`
  and no `state/apps/*/stack.lock` exists.
- Merge = fast-forward; rerun the self-test on main; if it fails, reset main to the pre-merge commit (own merge only) and report.
- After the merge: **restart the app session** (skills and agent definitions load at session start), then say
  "continue". Part A is active at once; Part B migrates itself at the next slice boundary (B2). No manual commands.

## Risks

| # | Risk | Likelihood / impact | Mitigation | Left over |
|---|---|---|---|---|
| R1 | Related-tests runs miss a regression in older tests | Med / Med | Slice gate runs the full verify and full E2E on the final code; DONE impossible without them | Found one round later instead of earlier |
| R2 | FLAKY hides an intermittent regression the slice itself caused | Low–Med / High | Only older untouched tests can be FLAKY; new tests must be deterministic; newly flaky tests are listed for the reviewer and in the final report | An intermittent regression can pass, but it is always reported |
| R3 | Image hash misses an input → E2E against stale code | Low / High | Hash the whole context minus explicit excludes (unknown → rebuild); self-test for unknown files | None found |
| R4 | Focus E2E overwrites official evidence | Low / High | Separate dirs, checked by `scratchEnvProblems`; self-test | None |
| R5 | A slice closes without a full E2E on its final code | Low / High | Close checks the full run's hash against the current code | None |
| R6 | Layer routing skips a needed builder | Low / Low | Unknown → both; round 1 always both; full gate catches cross-layer breaks | One extra round |
| R7 | test-retry plugin writes XML differently than expected | Low / Med | Smoke proof; without repeats the classification is today's behaviour | None |
| R8 | Docker cache mounts need BuildKit | Low / Med | env-check requires it | None |
| R9 | Migration damages a customised app file | Low / Med | Patches only exact known text; otherwise refuses | Manual change for customised files |
| R10 | Merge while an app workflow is running | Low / Med | `App paused: yes` + no stack.lock; Part A is resume-safe by design | None |
| R11 | Automerge lands broken code | Low / High | Self-test per package, smoke, post-merge self-test, rollback of the own merge | None |
| R12 | Frontend runner has no file filter | Med / Low | Frontend part runs in full and says so (it is ~8 s) | None |
| R13 | Folded runner commands hide which step failed | Low / Low | Only state changes and notes are folded; every gate keeps its sentinel | None |
| R14 | Smoke environment not available | Med / Low | No merge; report "ready, smoke not run" | Manual merge decision |
| R15 | Timing log grows or fails | Low / Low | Append-only, small; logging never fails a command | None |
| R16 | An agent finds yet another way to start Playwright or the stack | Low / Med | Guard covers every known form, red case per form; the refusal message and the agent rule remove the reason to improvise | A new, unknown invocation form until it is added |
| R17 | Stricter guard blocks a legitimate orchestrator action (e.g. a Docker command at subStep `none`) | Low / Low | Read-only commands stay allowed; all stack changes have a `stack.mjs` command | One blocked call, answered by the guard's message |
| R18 | Before the migration, rounds use full official E2E (fallback) | High / Low | Correct, just slower for slice 02 only; B2 migrates at the next boundary | Slower rounds until slice 02 is DONE |

## Overlap with the correctness plan
- `bin/migrate.mjs` is shared: `--speed` here, WP-M there.
- The correctness plan's WP-K (FALLOUT / LEAK) must keep FLAKY (A3) as a separate class; with D9 its isolation rerun
  runs in the slice gate's full verify instead of red-check.
- The correctness plan's WP-F (compile-first) fits on top of A2 unchanged.
- WP-Q (models) should use **medium** effort for builders now that speed is the priority.
